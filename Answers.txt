Q1. Explain how you would build an LLM-driven interview scoring system that is:
• Fair
• Consistent
• Non-biased
• Explainable

-> For fairness and non biasness, I would begin by masking the PIIs that can potentially add bias 
to the agent. Such PII may include name, gender, age or any other demographic information.

Also, it would be important to consider accent as a factor for biasness as well. The risks of a 
speech to text models incorrect interpretation due to difference in accent can cause the agent 
to assign lower points to candidate with higher value.

-> For consistency, the first idea is to ensure that the LLM is set to provide cold responses. 
Focusing on factual correctness and assessment of the candidate rather than creativity. 
For this, I would set the temperature parameter on the lower end around 0.1 to 0.3.

Second, I would verify the quality of each system prompt on user data. Only when the agent start 
providing similar responses to near similar user prompts it would be clear that the current system 
prompt is consistent and production ready.

-> For explanability, a dashboard which displays agent's scores with various parameter the user was 
tested on would be applicable. The dashboard displays the agent's questions. Along with the intended 
abilities tested and user's score on each of the intended ability.

Q2. Explain a method to detect fabricated answers or cheating patterns
(e.g., reading from screen, switching tabs, speaking pre-generated text).

-> To detect cheating patterns of fabricated approach a multi step approach would be required. 

Reading Detection:

1. Candidate's eye movement will be tracked (Open Source example:- https://github.com/NativeSensors/EyeGestures).
2. After the interview, the eye tracking data will parsed through a classifier model trained to detect reading movements
3. Or a clustering model to detect anomalous eye movements. The model can output a confidence score and higher confidence
score for reading can be flagged for human verification.

Switching tabs:

1. Using JavaScript, we can get the current state of the window and tabs opened.
2. Additionally if the state changes to another tab being opened or switched, it can trigger a cheating attempt detected.

Pre-generated texts:

1. Using text-to-speech models, we will get the speech transcripts of the candidate.
2. The transcripts will then be checked using an AI detector (Open source example:- https://github.com/bhaskatripathi/TypeTruth)

Q4. Describe how you would implement each of these during online interviews:
• Face detection
• Eye gaze tracking
• Tab change detection
• Voice consistency check
• Background noise analysis
• Multiple person detection
Explain your tech stack for each.

-> Face detection and multiple person detection can be solved using Object Detection models, such as Yolo. Yolo being a lightweight model can 
work on livestream to detect number of number of faces during the interview. Any number greater than 1 can be flagged for suspivious activity
later to be checked by a human in the loop.

Also deepface models (Open source example:- https://github.com/serengil/deepface) will provide a confidence score between the facial features from 
the candidate's ID card and the live stream.

-> For eye tracking gaze, as previously mentioned models (Open source example:- https://github.com/NativeSensors/EyeGestures) for eye tracking will be used.
Then the eye tracking pattern will be analyzed using a clustering model to detect if the eye tracking was anomaloous in nature (Detected as outlier).

-> Using JavaScript, we can get the current state of the window and tabs opened. Additionally if the state changes to another tab being opened or switched, 
it can trigger a cheating attempt detected.

-> Voice consistency will be checked using pre-trained models to analyzes real-time audio features like MFCC coefficients, pitch, and energy against a baseline 
voice sample captured during interview intro to detect unnatural modulation or synthetic speech patterns.​

-> Use pre-trained models to separate background noise with primary sound (Open source example:- https://huggingface.co/speechbrain/mtl-mimic-voicebank). Then the 
background noise can be analyzed separately.

Q6. Explain the steps to measure sentiment, emotion, and tone from an audio answer.

-> Using speech to text models such as whisper or open source models like wav2vec we will get the clear transcripts of the audio. We will analyze the transcript and
the audio separately. 

The audio will be tested on factors like pitch, loudness, MLFCC. And the audio features will then be used to classify for nuance detection, emotion.

Q7. Describe how you would measure communication quality, including:
• Pace
• Filler words
• Pauses
• Energy
• Coherency
(Simple bullet points.)

-> For pace, we will compute speaking rate as syllables per second or words per minute from ASR transcript divided by speech duration.
-> For filler words, we will transcribe with Whisper, count fillers ("um", "uh", "like") using regex. Then compute filler words ratio to total words.
-> For pauses, we will detect silence with energy thresholding. We will then measure pause frequency/duration ratio to speech time. Example: More than 15% indicates hesitation.

Q8. Design an end-to-end pipeline KrantiQ uses when a candidate takes an interview:
1. Candidate starts
2. Proctoring
3. Question delivery (audio/video avatar)
4. Answer capture (audio/video)
5. Transcription
6. LLM scoring
7. Skill extraction
8. Similarity analytics
9. Report generation
Write in clear bullet points.

-> Candidate Starts: Candidate will accesses the KrantiQ interview platform via a secure web link, where initial face detection using DeepFace verifies identity against uploaded ID, 
establishing a baseline voice sample and monitoring setup.​

Proctoring: Real-time monitoring activates with face detection (YOLO for multiple persons and away from keyboard), eye gaze tracking (e.g., EyeGestures for reading patterns), 
tab switching detection via JavaScript window state changes, voice consistency checks (MFCC, pitch against baseline), and background noise analysis (speechbrain models).​

Question Delivery: Questions delivered via audio/video avatar. System prompts will ensure fair, consistent delivery with low LLM temperature (0.1-0.3) for factual focus, 
masking PII like name, gender, age, and accent biases.​

Answer Capture: Candidate responses will be captured as audio/video streams. Continuous proctoring flags anomalies like face disappearance (e.g., 3-second alert via webcam feed), 
synthetic speech, or outliers in eye movements via clustering.​

Transcription: Audio transcribed using Whisper or wav2vec2 for accurate text. Separate audio features (pitch, loudness, MFCC) extracted for emotion/tone analysis.​

LLM Scoring: Transcripts fed to LLM with cold temperature (0.1-0.3) and verified prompts for consistent, non-biased scoring on factual correctness. 
PII masked to prevent demographic bias.​

Skill Extraction: LLM analyzes transcripts for targeted abilities (e.g., pace as words/minute, filler words via regex on "um/uh/like", 
pauses via energy thresholding, coherency via sentiment models). Scores aggregated per parameter.​

Similarity Analytics: Embeddings from transcripts compared for cheating (e.g., AI-generated text detection via TypeTruth). 
Anomalous patterns like pre-generated speech or outlier gaze flagged with confidence scores.​

Report Generation: Dashboard compiles scores per ability/question, with explainable breakdowns, proctoring flags for human review, and visualizations of metrics like speaking rate. 
Pause ratios (>15% hesitation), energy, and overall fairness.

Q11. Explain how you would reduce cloud costs for:
• Video processing
• Audio processing
• LLM scoring
• Embeddings
• Storage

-> For video processing, to avoid real time cloud GPU cost, a lightweight object detection model such as YOLO will run on client side, to detect multiple faces or missing face. And the anomalous
event's timestamp will be stored separately.

-> For audio processing, cpu optimized models, example Wav2Vec can run on serverless function example lambda, to run the audio models on-demand.

-> For LLM scoring, we will use models at low temperature and enable caching prompt templates to save cost on repetitive user responses.

-> For embeddings, we will use cpu efficient models or frameworks, example fastembed (As used in Section 1). Also reuse embeddings for same questions by the Agent.

-> For storage, we will compress the video files and reduce the fps to reduce storage after processing.
